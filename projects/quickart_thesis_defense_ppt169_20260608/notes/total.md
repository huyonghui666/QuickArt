# 01_封面

各位老师好，我的毕业设计答辩题目是《基于多模型融合与Flutter的跨平台AI内容生成系统设计与实现》。本次汇报我会重点介绍系统是如何设计与实现的，以及系统测试结果，最后再对全文做一个总结与展望。

# 02_课题背景与研究意义

这一页我简要说明课题背景。随着生成式人工智能从文本生成逐渐扩展到图像、视频等多模态创作，移动端用户对“随时创作、即时分享”的需求越来越强。但现有 AIGC 应用普遍存在模型能力分散、创作流程割裂、工程协同复杂等问题。因此，本课题希望构建一套面向移动端场景的完整系统，把多模型能力、跨平台客户端、异步任务机制和业务闭环统一起来。

# 03_系统目标与功能概览

QuickArt 的目标不是只实现某一个 AI 功能，而是构建一个完整的移动端 AIGC 创作系统。系统核心能力包括文生图、图生图、文生视频、图生视频以及 AI 换脸。同时，系统还包含认证登录、工作室任务管理、结果分享和支付积分等业务模块。也就是说，这套系统覆盖了从用户创作到结果消费的完整链路，而不是一个孤立的模型调用演示。

# 04_系统总体架构设计

系统整体采用“客户端、服务端、云端模型服务”三层端云协同架构。客户端基于 Flutter 构建，负责用户交互、页面渲染和任务状态展示，并通过 Riverpod 管理状态、GoRouter 管理路由，以及 SQLite 与 Hive 进行本地持久化。服务端基于 Spring Boot 3 和 Kotlin 搭建，主要负责业务编排、多模型接口统一封装、用户鉴权以及数据持久化。云端模型层则提供具体的 AI 能力，其中火山方舟负责图像和视频生成，Magic Hour 负责 AI 换脸，阿里云 OSS 负责结果文件存储与分发。这样的三层结构使各层职责边界清晰，也方便后续扩展新的模型能力。

# 05_核心业务流程设计

从用户视角来看，系统的核心流程可以概括为五步。第一步，用户登录后进入创作页，输入提示词或者上传图片并发起生成请求。第二步，客户端将请求发送到服务端，由服务端统一封装并调度对应的模型接口。第三步，服务端创建任务记录并返回 taskId，随后在后台异步执行长耗时任务。第四步，当任务状态变化或者结果生成完成后，服务端通过 WebSocket 将状态和结果主动推送回客户端。第五步，客户端在工作室中展示历史任务、状态变化和结果内容，并支持预览与分享。这个流程体现了系统从创作到结果管理的完整闭环。

# 06_功能模块设计与实现

在功能实现上，系统主要由五个模块协同工作。认证登录模块接入微信扫码授权，实现 OAuth 回调、JWT 签发和登录态持久化。QuickArt 创作模块是系统核心入口，承担文生图、图生图和模板化创作。工具模块进一步扩展了文生视频、图生视频和 AI 换脸能力，使系统支持更多内容生成场景。工作室模块负责管理历史任务、实时状态更新、结果预览和分享，是任务闭环的重要承接端。支付与积分模块则完成套餐展示、支付宝下单、支付回调和积分到账，形成了商业化业务链路。右侧这些界面截图也说明系统已经完成真实界面落地，而不只是停留在设计层面。

# 07_数据库与关键数据设计

数据库设计的重点在于既要保证业务一致性，也要支撑长耗时任务追踪和客户端恢复能力。服务端核心表包括 users、generation_tasks、payment_orders 和 points_ledger。users 表保存用户基本信息和积分余额；generation_tasks 表统一记录图像、视频和换脸任务状态，是异步任务机制的核心；payment_orders 表记录支付订单的全生命周期；points_ledger 表记录每一笔积分变动，并通过业务主键实现幂等防重。除此之外，客户端还使用 SQLite 保存工作室任务记录，用于在应用重启或网络中断后恢复任务状态。可以看到，系统的数据建模并不是简单存表，而是围绕任务、支付、积分和恢复这几个关键问题展开设计的。

# 08_异步任务与WebSocket实时推送

这一页是本系统实现中的关键部分。因为图像和视频生成都属于长耗时任务，所以服务端不能采用同步阻塞方式处理。系统的做法是：在用户发起请求后，服务端先创建任务并立即返回 taskId，这样接口响应速度不会受到生成耗时影响；随后任务进入后台异步执行；任务状态变化或生成结果完成后，服务端再通过 WebSocket 主动推送给客户端；客户端收到推送后，会实时更新工作室中的任务状态和结果内容。另外，为了保证业务正确性，客户端通过 SQLite 实现任务恢复，支付积分模块通过业务键实现幂等校验，防止重复回调导致积分重复到账。可以说，这一机制是系统能够稳定落地在移动端场景中的核心。

# 09_系统测试与结果分析

系统测试主要从测试环境配置和功能测试两个方面展开。功能测试覆盖了认证登录、QuickArt 创作、工具模块、工作室模块以及支付与积分模块五个核心部分。认证登录测试验证了微信授权、JWT 签发、本地持久化与路由拦截链路；QuickArt 创作测试验证了文生图、图生图和模板创作，以及异步提交加 WebSocket 推送的完整链路；工具模块测试覆盖了视频生成和 AI 换脸，同时补充了无人脸图片的异常路径；工作室模块测试验证了任务展示、状态更新以及应用重启后的任务恢复；支付与积分模块测试则重点验证了下单、回调、到账和幂等校验。从论文测试结果来看，这些核心模块均已通过验证，说明系统在功能完整性和交互流畅性上达到了预期目标。

# 10_总结

对本文工作做一个总结。本课题完成了一套可运行、可扩展、具备业务闭环的跨平台 AI 内容生成系统。首先，基于 Flutter 实现了跨平台移动端客户端；其次，把图像、视频、AI 换脸等多模型能力整合进统一的业务体系中；最后，围绕异步长任务、实时状态同步、支付积分以及本地恢复等工程问题，完成了较为系统的落地实现。因此，这项工作的价值不只是做出了若干功能，而是完成了一套面向真实业务流程的工程化系统方案。
